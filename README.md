# WorkpulsActivityReport

.NET 8 კონსოლის აპლიკაცია. კითხულობს Workpuls/Insightful აგენტის ლოგებს და ქმნის ვიზუალურ HTML რეპორტს:
რამდენ ხანს იყავი აქტიური, უმოქმედო ან ჩაკეტილი, დღეების და კვირების მიხედვით, წუთის სიზუსტის დროის ხაზებით.

აპლიკაცია **მხოლოდ კითხულობს** ლოგებს. აგენტს და მის ფაილებს არ ცვლის. ადმინის უფლებები არ სჭირდება.

## როგორ მუშაობს

1. **აგროვებს ლოგებს.** ყოველ გაშვებაზე `%APPDATA%\workpuls-agent\logs`-დან ახალ და გაზრდილ ფაილებს აკოპირებს
   აპლიკაციის საქაღალდეში (`data\archive`, gzip-ით შეკუმშული):
   - `main\YYYY-MM-DD.log*`: ამ კომპიუტერის ლოგები (სახელი რეპორტში: `--name`, ნაგულისხმევად `PC`).
   - `main\<სახელი>\YYYY-MM-DD.log*`: სხვა კომპიუტერის ლოგები. მაგალითად, `main\Laptop\` რეპორტში `Laptop` სახელით ჩანს.
   - `tracker\tracker_*.log`: RDP/OTHER და Injected მოქმედებების რაოდენობა.
   - `--import <სახელი>=<საქაღალდე ან .zip>`: სხვა კომპიუტერის ლოგები ნებისმიერი ადგილიდან.

   აგენტი მხოლოდ ბოლო ~10 ფაილს ინახავს, არქივი კი არაფერს შლის. ამიტომ თუ აპლიკაციას ყოველ ~7 დღეში ერთხელ გაუშვებ,
   მთელი ისტორია დაგროვდება.

   თუ კოპირება ვერ ხერხდება (უფლებები, დისკი, დაბლოკილი ფაილი ან საერთოდ მიუწვდომელი `data\`), ეს ფაილები **პირდაპირ ლოგების
   საქაღალდიდან იკითხება** და რეპორტი მაინც იქმნება. ამ რეჟიმში მხოლოდ ის პერიოდი ჩანს, რომელიც აგენტს ჯერ კიდევ შენახული აქვს.
   თუ `reports\`-ში ჩაწერა ვერ ხერხდება, რეპორტი იწერება `%TEMP%\WorkpulsActivityReport\reports`-ში.
2. **აანალიზებს.** ყოველ წუთს ანიჭებს მდგომარეობას: აქტიური, always-active, უმოქმედო, ჩაკეტილი ან მონაცემი არ არის.
   უკვე დამუშავებული დღეები ინახება `data\cache`-ში.
3. **ქმნის რეპორტს.** იქმნება `reports\report.html` და მისი თარიღიანი ასლი, რომელიც ბრაუზერში იხსნება. რეპორტში არის:
   - კვირების ცხრილი მთელ დაგროვილ პერიოდზე;
   - პერიოდის არჩევა: ბოლო კვირა, წინა გაშვების შემდეგ, მთელი პერიოდი ან ნებისმიერი კვირა;
   - დღეების ცხრილი, დროის ხაზები და განმარტებები.

რამდენიმე კომპიუტერის შემთხვევაში (მაგ. ლეპტოპიდან RDP-ით PC-ზე) **„ჯამური აქტიური“** არის დრო, როცა ერთ კომპიუტერზე მაინც აქტიური იყავი.
ასე ერთდროული დრო ორჯერ არ ითვლება. თუ `main\` ქვესაქაღალდე (მაგ. `Laptop`) არ არსებობს და `--import` არ არის მითითებული, რეპორტი
**ერთი მოწყობილობისაა**: არ ჩანს დამთხვევის სვეტი, გაერთიანებული ხაზი და RDP-ის ახსნა.

`main\`-ის ქვესაქაღალდე (მაგ. `New folder`) ცალკე მოწყობილობად **არ ითვლება**, თუ მასში ამავე კომპიუტერის ლოგების ასლია. ამას აპლიკაცია შინაარსით ამოწმებს: ორი სხვადასხვა მოწყობილობის ლოგი ერთნაირი ხაზით ვერ დაიწყება. ასეთი ასლიდან აიღება მხოლოდ ის დღეები, რომლებიც აგენტს უკვე წაშლილი აქვს, და ისინიც ამ კომპიუტერს მიეწერება.

### ClickOnce ინსტალაცია

ClickOnce აპლიკაციას აყენებს `%LOCALAPPDATA%\Apps\2.0\...` საქაღალდეში. ეს საქაღალდე ყოველ განახლებაზე იცვლება და წაშლისას იშლება.
ამიტომ ClickOnce-ით დაყენებისას `data\` და `reports\` ინახება აქ: **`%LOCALAPPDATA%\WorkpulsActivityReport`**.
ძველი ვერსიების `data\archive` (თუ `Apps\2.0`-ში დარჩა) ავტომატურად გადმოიტანება.
ჩვეულებრივი (`publish\` საქაღალდიდან) გაშვებისას ყველაფერი ისევ exe-ის გვერდით ინახება.

## გაშვება

```powershell
# ერთხელ: build
dotnet publish src\WorkpulsActivityReport -c Release -o publish

# ყოველ ჯერზე (data\ და reports\ publish\ საქაღალდეში იქმნება)
.\publish\WorkpulsActivityReport.exe
```

პარამეტრები (`--help`):

| პარამეტრი | აღწერა |
|---|---|
| `--logs <dir>` | აგენტის ლოგების საქაღალდე (ნაგულისხმევი: `%APPDATA%\workpuls-agent\logs`) |
| `--name <name>` | ამ კომპიუტერის სახელი (ნაგულისხმევი: `PC`) |
| `--import <Name>=<path>` | სხვა კომპიუტერის ლოგები (საქაღალდე ან `.zip`). შეიძლება რამდენჯერმე მიეთითოს |
| `--data <dir>` / `--out <dir>` | არქივის / რეპორტების საქაღალდე |
| `--no-collect` | ახალ ლოგებს არ აგროვებს, რეპორტს მხოლოდ არქივიდან ქმნის |
| `--no-open` | რეპორტს ბრაუზერში არ ხსნის |

ტესტები: `dotnet test`

## შეზღუდვები

- შედეგი მიახლოებითია. Insightful-ის ზუსტი წესები (idle-ის ზღვარი, პროდუქტიულობა) სერვერზე ითვლება.
- აპლიკაციების და საიტების სახელები ლოგში არ იწერება, ამიტომ პროდუქტიული დრო ვერ ითვლება.
- `data\` და `reports\` პირად მონაცემებს შეიცავს და `.gitignore`-შია დამატებული.
